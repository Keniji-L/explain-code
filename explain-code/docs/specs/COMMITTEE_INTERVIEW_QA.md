# คู่มือถาม–ตอบสำหรับนำเสนอและสัมภาษณ์กรรมการ (Committee Interview Q&A)

> เอกสารสรุปแนวทางการตอบคำถามสำหรับโครงงาน **CODE COOL** — แพลตฟอร์มฝึกเข้าใจและอธิบายโค้ดผ่านดันเจี้ยน RPG 2D และตัวช่วยวิเคราะห์โค้ดด้วย AI

---

## หมวดที่ 1: แนวคิดและที่มาของโครงงาน (Problem & Motivation)

### Q1: ทำไมถึงทำโปรเจกต์นี้ ปัญหาที่แก้คืออะไร?
**แนวทางตอบ:**
- ปัญหาหลักของผู้เรียนเขียนโปรแกรมยุคนี้ (โดยเฉพาะยุคที่มี AI ช่วยเขียนโค้ด) คือ **"เขียนโค้ดได้ / ก๊อปโค้ดมารันผ่าน แต่อธิบายไม่ได้ว่าโค้ดทำงานยังไงทีละบรรทัด"**
- เว็บฝึกเขียนโค้ดทั่วไปมักเน้น **การเขียนให้ผ่าน Test Case** หรือ **ทำควิซตัวเลือกธรรมดา** ซึ่งวัดผลลัพธ์ปลายทางได้ แต่ไม่ค่อยได้ฝึก **การอ่าน ไล่การทำงาน และอธิบายเหตุผล**
- เราจึงสร้าง **CODE COOL** เพื่อเปลี่ยนจากการทำแบบฝึกหัดน่าเบื่อ เป็น **เกม RPG ดันเจี้ยน 2D** ที่ผู้เล่นต้อง "เข้าใจโค้ด" เพื่อเอาชนะมอนสเตอร์และผ่านด่าน

### Q2: กลุ่มเป้าหมายคือใคร และต่างจากเว็บฝึกโค้ดอื่นอย่าง Codecademy, LeetCode หรือ Kahoot อย่างไร?
**แนวทางตอบ:**
- **กลุ่มเป้าหมาย:** นักเรียน/นักศึกษาที่กำลังเริ่มต้นเรียนเขียนโปรแกรม และครูผู้สอนวิชาวิทยาการคำนวณ/เขียนโปรแกรมในห้องเรียน
- **จุดต่างหลัก:**
  1. **LeetCode / HackerRank:** เน้นโจทย์อัลกอริทึมและเขียนโค้ดแก้ปัญหา แต่ไม่เหมาะกับมือใหม่ที่ยังอ่านโค้ดไม่ออก
  2. **Kahoot / Quizizz:** เป็นควิซตอบไว เน้นความจำ ไม่ได้มีโครงสร้างวัดความเข้าใจโค้ดเชิงลึกและไม่มีโหมดวางโค้ดตัวเอง
  3. **CODE COOL:** ผสาน **Block Model + PRIMM** เข้ากับเกม RPG 2D, รองรับการวางโค้ดของตัวเองมาแปลงเป็นดันเจี้ยนส่วนตัว (`/explain`), และมี **Analytics รายจุดอ่อนสำหรับครู** (`/teacher`)

## หมวดที่ 2: ทฤษฎีการเรียนรู้รองรับ (Pedagogy: Block Model & PRIMM)

### Q3: ทำไมถึงใช้ Block Model ในการออกแบบคำถาม?
**แนวทางตอบ:**
- **Block Model** (Carsten Schulte) เป็นกรอบวัดความเข้าใจโปรแกรมที่แบ่งความเข้าใจออกเป็น **2 แกน (3 ระดับความเข้าใจ × 2 ขอบเขต)** รวม 6 เซลล์ (`T1, E1, F1, T2, E2, F2`):
  - **Text Surface (`T1`, `T2`):** เข้าใจโครงสร้างไวยากรณ์ คำสั่ง ตัวแปร และความสัมพันธ์ของบล็อกโค้ด
  - **Program Execution (`E1`, `E2`):** ไล่ลำดับการทำงานทีละบรรทัดและติดตามค่าตัวแปร/ผลลัพธ์ได้
  - **Function / Purpose (`F1`, `F2`):** เข้าใจว่าโค้ดส่วนนี้หรือทั้งโปรแกรมทำหน้าที่อะไรและมีเป้าหมายเพื่ออะไร
- การใช้ Block Model ทำให้ระบบไม่ได้ถามแค่ *"ผลลัพธ์คืออะไร"* อย่างเดียว แต่รู้ด้วยว่าผู้เรียน **อ่อนมิติไหน** (เช่น อ่าน syntax ออก แต่ไล่ loop ไม่เป็น หรือไล่ได้แต่ไม่เข้าใจภาพรวม)

### Q4: แนวคิด PRIMM ถูกนำมาใส่ในเกมอย่างไร?
**แนวทางตอบ:**
- เราผสานแนวคิด **PRIMM (Predict – Run – Investigate – Modify – Make)** เข้าไปในประสบการณ์การเล่นดันเจี้ยน:
  - **Predict & Investigate:** ในห้องดันเจี้ยนมี *"คัมภีร์โค้ดประจำด่าน"* ที่กดสลับดูโค้ดเต็มและ **ไล่การทำงานทีละบรรทัด (Line-by-Line Trace)** พร้อมค่าตัวแปรก่อนสู้มอนสเตอร์
  - **Run & Modify:** หลังปราบมอนสเตอร์และเปิดประตูได้ มีภารกิจโบนัสให้ลองแก้ไขโค้ดและกดรันทดสอบจริง เพื่อรับโบนัส XP
  - **Make / Own Code:** ผู้เรียนสามารถนำโค้ดที่ตัวเองเขียนในหน้า `/explain` มาแปลงเป็นด่านดันเจี้ยนส่วนตัวได้

### Q5: ถ้าคำถามมี 4 ตัวเลือก จะป้องกันไม่ให้นักเรียน "เดาจากความยาวประโยค" ได้อย่างไร?
**แนวทางตอบ:**
- เราสร้างระบบ **`rebalanceChoicesIfNeeded`** (`app/lib/question-choice-balance.ts`) เพื่อปรับสมดุลความยาวของตัวเลือกทั้งฝั่ง AI และ Fallback ไม่ให้ข้อที่ถูกต้องยาวกว่าตัวลวงจนสังเกตได้ง่าย พร้อมทั้งสลับลำดับตัวเลือกแบบกำหนด seed (`shuffleChoicesPreservingCorrect`) ทุกครั้งที่เริ่มเล่น

## หมวดที่ 3: ระบบเกมและการออกแบบประสบการณ์ผู้เรียน (Game Design & UX)

### Q6: ทำไมต้องเป็นเกม RPG 2D แทนที่จะเป็นเว็บควิซธรรมดา?
**แนวทางตอบ:**
- เกม RPG สร้างแรงจูงใจภายใน (Intrinsic Motivation) ผ่านเป้าหมายระยะสั้น–ยาว:
  - ผู้เรียนควบคุมตัวละครเดินสำรวจแผนที่ 2D, เก็บ **Coins / XP**, บริหาร **HP (หัวใจ) และ MP (Focus)** ข้ามชั้น และกดเซฟเกม (`Save Game`) กลับมาเล่นต่อได้
  - มีคลาสตัวละครที่สกิลต่างกันจริง เช่น โล่ป้องกันดาเมจ (`shieldCharges`) หรือสกิลฟื้นเลือดของ Rogue
  - มีห้องหลายรูปแบบ เช่น มอนสเตอร์, บอส, หีบสมบัติ และ **Mimic Chest** (หีบหลอก) ทำให้การทำโจทย์ไม่ซ้ำซาก

### Q7: รองรับภาษาอะไรบ้าง และใช้งานบนมือถือได้ไหม?
**แนวทางตอบ:**
- รองรับ **7 ภาษาโปรแกรม** ได้แก่ Python, JavaScript, TypeScript, C++, Java, SQL และ HTML พร้อมระบบสลับภาษา UI และคำถาม **ไทย / อังกฤษ (TH/EN)**
- รองรับการเล่นทั้งบนเดสก์ท็อป (WASD / ปุ่มลูกศร / คีย์ลัด `1–4` ซึ่งรองรับแม้เปิดคีย์บอร์ดภาษาไทยอยู่) และบนมือถือด้วย **D-Pad จำลอง** และแถบนำทางด้านล่าง

### Q8: เมื่อผู้เรียนตอบผิด ระบบช่วยสอนอย่างไร ไม่ใช่แค่ขึ้นว่า "ผิด"?
**แนวทางตอบ:**
- ใน `BattleOverlay` เมื่อตอบผิด ระบบจะ **ไม่เฉลยข้อถูกทันที** เพื่อไม่ให้ผู้เล่นกดมั่วแล้วจำเฉลย แต่จะแสดง **คำอธิบายแนวทางคิด (Concept Guidance)** และเมื่อกดลองใหม่ ระบบจะตัดตัวเลือกที่ตอบผิดออกให้ผู้เรียนวิเคราะห์ต่อจากตัวเลือกที่เหลือ

## หมวดที่ 4: สถาปัตยกรรมระบบและเทคโนโลยี (Architecture, AI & Database)

### Q9: ใช้เทคโนโลยีอะไรบ้างในการพัฒนา?
**แนวทางตอบ:**
- **Frontend & Backend:** Next.js 16 (App Router, Turbopack), TypeScript, Tailwind CSS
- **Database & Auth:** Supabase (PostgreSQL + Auth) พร้อมโหมด fallback สำหรับข้อมูลเริ่มต้นและการทำงานแบบออฟไลน์
- **AI Engine:** Google Gemini API (`gemini-3.5-flash-lite` → `gemini-3.6-flash` → `gemini-3.8-flash` แบบ fallback อัตโนมัติ)

### Q10: ถ้า Gemini API โควตาหมด หรืออินเทอร์เน็ตมีปัญหา ระบบจะล่มไหม?
**แนวทางตอบ:**
- **ไม่ล่มครับ** เราออกแบบระบบสำรอง 2 ชั้น:
  1. **Model Fallback Chain + Overall Deadline:** ใน `gemini-client.ts` ถ้าโมเดลหลักติด Rate Limit (429) หรือไม่พร้อมใช้งาน (503/404) จะสลับไปยังโมเดลสำรองใน Chain อัตโนมัติภายใต้กรอบเวลา `overallDeadline`
  2. **Deterministic Rule-Based Fallback:** ทั้งระบบอธิบายโค้ด (`/api/explain`), สร้างดันเจี้ยนจากโค้ด (`/api/explain/to-dungeon`), และตรวจคำอธิบาย (`/api/interrogate`) มีตัววิเคราะห์และชุดสร้างโจทย์แบบ Deterministic สำรองอยู่เสมอ

### Q11: ครูผู้สอนได้ประโยชน์อะไรจากระบบนี้บ้าง?
**แนวทางตอบ:**
- ในหน้า `/teacher` ครูสามารถ:
  1. สร้างและจัดการ **คอร์สเรียน & บทเรียน** ทั้งแบบสาธารณะ (Public) และแบบส่วนตัว (Private ต้องใช้ **Join Code** เข้าร่วม)
  2. ใช้ AI ช่วยสร้างโจทย์คำถามทั้งสำหรับบทเรียนและดันเจี้ยนโดยอิงจากเนื้อหาบทเรียน
  3. ดู **Dashboard & Analytics** วิเคราะห์คะแนนจุดอ่อนของนักเรียนแยกตาม **6 เซลล์ Block Model** และส่งออกข้อมูล/ดูความคืบหน้าผู้เรียนได้

## หมวดที่ 5: ความปลอดภัย ความเป็นส่วนตัว และความน่าเชื่อถือ (Security & PDPA)

### Q12: มีมาตรการดูแลความเป็นส่วนตัวของผู้เรียน (PDPA) อย่างไร?
**แนวทางตอบ:**
- ออกแบบตามแนวทาง **Privacy-First (No Personal Email Required):**
  - นักเรียนสมัครและเข้าสู่ระบบด้วย **ชื่อเล่นสมมติ + รหัส PIN 4 หลัก** โดยไม่ต้องกรอกอีเมลส่วนตัว เบอร์โทร หรือข้อมูลระบุตัวตนจริง
  - ครูสมัครด้วย Username + Password + รหัสเชิญครู (**Invite Code**)

### Q13: ป้องกันการโกงคำตอบหรือการเจาะสิทธิ์หลังบ้านอย่างไร?
**แนวทางตอบ:**
- **API Key & Secrets:** `GEMINI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY` และ Secret สำหรับลงนาม Session อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น ไม่ส่งออกไปฝั่ง Client
- **Server-Side Verification:**
  - เฉลยคำถามดันเจี้ยน (`/api/dungeon/answer`) และ Quiz ท้ายบทเรียน (`POST /api/lms` action `grade-lesson-quiz`) ถูกซ่อนจาก public GET และตรวจคะแนนฝั่งเซิร์ฟเวอร์ทั้งหมด
  - ป้องกันการปั๊ม XP/Coins ซ้ำในข้อเดิม (`room_attempts`) และห้ามส่งคำตอบหลัง `game_over`
  - คอร์สส่วนตัวซ่อน `join_code` จาก public GET และตรวจรหัสฝั่งเซิร์ฟเวอร์
- **Role & Route Protection:** `proxy.ts` และ API ฝั่ง `/api/teacher/*` ตรวจสิทธิ์จากฐานข้อมูล `profiles` และสถานะ `teacherStatus === "approved"`
- **Sandbox Execution:** ตัวรันโค้ดจำลองในเบราว์เซอร์ปิดกั้นการเข้าถึง `window`, `document`, `fetch`, `localStorage`, `sessionStorage` เพื่อความปลอดภัย

## หมวดที่ 6: ข้อจำกัดปัจจุบันและแนวทางพัฒนาต่อ (Limitations & Future Work)

### Q14: ระบบยังมีข้อจำกัดตรงไหนบ้าง และถ้าพัฒนาต่อจะเพิ่มอะไร?
**แนวทางตอบ (ตอบอย่างตรงไปตรงมาและมีวิสัยทัศน์):**
1. **ตัวรันโค้ดหลายภาษา (Python/C++/Java/SQL):** ปัจจุบันใช้ตัวจำลองบนเบราว์เซอร์เพื่อความเร็วและไม่ต้องเสียค่า Sandbox Server ภายนอก หากขยายระดับมหาวิทยาลัยอาจเชื่อมต่อ Docker/Judge0 API เพื่อรันโค้ดจริงเต็มรูปแบบ
2. **ระบบเศรษฐกิจในเกม (Coins Shop & Streak):** ปัจจุบันเก็บ Coins/XP ข้ามชั้นได้แล้ว ในอนาคตสามารถเพิ่ม **ร้านค้าระหว่างชั้น** ให้ใช้ Coins ซื้อบัฟ/สกิน และระบบ **Daily Streak / Badges** เพื่อเพิ่มแรงจูงใจระยะยาว
3. **ลูกเล่นเฉพาะของบอส:** สามารถเพิ่มกลไกพิเศษเฉพาะบอสแต่ละด่าน เช่น ด่านจับเวลา หรือโจทย์เรียงลำดับการทำงานของโค้ด

## หมวดที่ 7: เคล็ดลับการตอบคำถามสั้นๆ หน้างาน (Rapid-Fire Tips)
- **ถ้ากรรมการถาม "ต่างจาก ChatGPT ยังไง?"** → ตอบว่า *"ChatGPT ให้คำตอบสำเร็จรูป ทำให้เด็กไม่ได้คิด แต่ CODE COOL บังคับให้เด็กอ่าน คาดเดา ไล่ทีละบรรทัด และอธิบายกลับมาผ่านเกมที่มีโครงสร้าง Block Model และครูติดตามจุดอ่อนรายคนได้ครับ"*
- **ถ้ากรรมการถาม "ถ้าไม่มีอินเทอร์เน็ตหรือ API หมดโควตา?"** → ตอบว่า *"มี Deterministic Fallback ฝั่งเซิร์ฟเวอร์และ Seed Data ในระบบ ทำให้ยังเล่นดันเจี้ยน วิเคราะห์โค้ดพื้นฐาน และทำบทเรียนต่อได้ไม่สะดุดครับ"*
- **ถ้ากรรมการขอดูจุดเด่นทางเทคนิคที่ภูมิใจ** → เปิดให้ดู 3 จุด:
  1. หน้า `/explain` → วางโค้ดแล้วกดสร้างเป็นด่านดันเจี้ยนส่วนตัว
  2. หน้า `/courses` → เลือกภาษา ลุยดันเจี้ยน 2D + คัมภีร์โค้ดไล่ทีละบรรทัด
  3. หน้า `/teacher` → ดูแผนภาพจุดอ่อนผู้เรียนตาม Block Model 6 เซลล์
